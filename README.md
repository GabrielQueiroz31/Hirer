# Hirer

**Plataforma de recrutamento e seleção web e mobile baseada em compatibilidade profissional.**

## Sobre o projeto

O Hirer é uma plataforma web e mobile que conecta candidatos e empresas por meio de um sistema de compatibilidade profissional, tornando o processo de recrutamento mais simples, rápido e eficiente.

## Funcionalidades

- Cadastro de candidatos e empresas.
- Criação e gerenciamento de perfis profissionais.
- Cadastro e divulgação de vagas.
- Sistema de compatibilidade entre candidatos e vagas.
- Demonstração de interesse e criação de Match.
- Chat entre candidatos e empresas após o Match.

## Objetivo

Facilitar a conexão entre profissionais e empresas, reduzindo dificuldades comuns nos processos seletivos e aproximando candidatos de oportunidades compatíveis com seus perfis.

# Requisitos do Sistema — Hirer

## 1. Requisitos Funcionais (RF)

| ID | Requisito |
|---|---|
| RF01 | O sistema deve permitir o cadastro de candidatos. |
| RF02 | O sistema deve permitir o cadastro de empresas. |
| RF03 | O sistema deve permitir que os usuários realizem login e logout. |
| RF04 | O sistema deve permitir a recuperação de senha. |
| RF05 | O candidato deve poder criar e editar seu perfil profissional. |
| RF06 | O candidato deve poder adicionar experiências, habilidades, formação acadêmica e currículo. |
| RF07 | As empresas devem poder criar e gerenciar perfis empresariais. |
| RF08 | As empresas devem poder cadastrar, editar e excluir vagas de emprego. |
| RF09 | O sistema deve exibir vagas compatíveis com o perfil do candidato. |
| RF10 | O candidato deve poder demonstrar interesse ou rejeitar uma vaga por meio de interações de deslizar (like e dislike). |
| RF11 | As empresas devem poder visualizar candidatos interessados em suas vagas. |
| RF12 | O sistema deve identificar correspondências quando candidato e empresa demonstrarem interesse mútuo (match). |
| RF13 | O sistema deve permitir a comunicação entre candidatos e empresas após um match. |
| RF14 | O sistema deve permitir que candidatos acompanhem o andamento de suas candidaturas. |
| RF15 | O sistema deve disponibilizar filtros de busca por localização, área profissional, modalidade de trabalho e faixa salarial. |
| RF16 | O sistema deve enviar notificações sobre novos matches, mensagens e atualizações de candidaturas. |
| RF17 | O sistema deve permitir que usuários visualizem e gerenciem suas preferências. |
| RF18 | O sistema deve permitir que usuários encerrem ou excluam suas contas. |
| RF19 | O sistema deve permitir que administradores gerenciem usuários, empresas e vagas. |

## 2. Requisitos Não Funcionais (RNF)

| ID | Requisito |
|---|---|
| RNF01 | O sistema deve possuir uma interface intuitiva e de fácil utilização. |
| RNF02 | A plataforma deve ser responsiva e funcionar em diferentes tamanhos de tela. |
| RNF03 | O sistema deve ser compatível com navegadores modernos. |
| RNF04 | O aplicativo mobile deve ser compatível com Android e iOS. |
| RNF05 | As senhas dos usuários devem ser armazenadas utilizando algoritmos seguros de hash. |
| RNF06 | A comunicação entre cliente e servidor deve utilizar HTTPS. |
| RNF07 | O sistema deve proteger os dados pessoais dos usuários, respeitando a LGPD. |
| RNF08 | As principais funcionalidades devem apresentar tempo de resposta preferencialmente inferior a 2 segundos em condições normais de uso. |
| RNF09 | O sistema deve possuir disponibilidade mínima de 99% ao mês. |
| RNF10 | O sistema deve ser desenvolvido de forma modular, facilitando futuras manutenções e atualizações. |
| RNF11 | O sistema deve permitir o crescimento da quantidade de usuários sem comprometer significativamente seu desempenho. |
| RNF12 | O sistema deve validar os dados inseridos pelos usuários para evitar informações inválidas ou inconsistentes. |
| RNF13 | O sistema deve possuir mecanismos de backup para recuperação de dados. |
| RNF14 | A interface deve seguir boas práticas de acessibilidade. |
| RNF15 | O sistema deve apresentar mensagens claras de erro e confirmação das operações realizadas. |
